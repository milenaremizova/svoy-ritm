# Свой ритм

Идея фичи для геймификации и ее реализация для Яндекс Лавки: стрик, который считает серию не по календарным дням, а по личному ритму заказов. Если человек заказывает примерно раз в три дня, серия держится, пока следующий заказ приходит в его окне.

Классический ежедневный стрик для продуктовой доставки не работает: продукты почти никто не заказывает каждый день, поэтому серия рвётся у большинства уже на второй день. Персональный ритм, подстраивающийся под пользователя, решает эту проблему, идея для удержания и частоты заказов, а не привлечения новых пользователей.

Пет-проект сделан поверх существующего интерфейса Лавки, своей валюты и своего раздела не вводит, работает на тех же монетках и в том же магазине призов.

**Статус: в разработке.** Что сделано и что нет.

## Механика

Серия состоит из остановок (`stops`). Остановка засчитывается за один **доставленный** заказ в окне ритма. Это закрывает схему «заказал и отменил»: до доставки звено висит в статусе «в пути» и на серию не влияет.

Ритм (`personalRhythmDays`) считается как медиана интервалов между последними пятью доставками, округляется и зажимается в 2-7 дней. Пока доставок меньше трёх, ритм неизвестен, пользователь видит онбординг вместо маршрута.

Дедлайн следующей остановки = время доставки + ритм + 1 день. Лишний день это запас, чтобы серия не рвалась из-за пары часов. Фиксируется в момент засчитывания и задним числом не меняется, даже если ритм пересчитался.

Заморозки (`freezesForStreak`) тратятся автоматически, когда окно истекло: продлевают дедлайн на один ритм. Новая серия стартует с одной, вторая выдаётся на 7-й остановке, больше двух не копится. Числа взяты из экспериментов Duolingo: две заморозки работали лучше одной, три не лучше двух.

С 7-ой остановки включается второй уровень (`levelForIncrease`): остановка засчитывается только за заказ от 50% личного медианного чека, взамен награда растёт в 1,5 раза. До этого порога нет, так как задача первых остановок замотивировать, а не отфильтровать, а в дальнейшем корректировать условия, сделав их гибче.

Награда за остановку переменная (15–40 монеток), на вехах 3/7/14 добавляется бонус. Случайность выводится из id заказа, а не из `Math.random()` — одинаковый id всегда даёт одинаковую награду, повторная обработка события не меняет сумму. Сверху потолок в процентах от суммы заказа, чтобы фича не уходила в убыток.

## Стек

**Frontend:**

- React + TypeScript + Vite
- react-router-dom
- CSS Modules + CSS-переменные в `tokens.css` — цвета и радиусы выставляются один раз на корне, компоненты не знают конкретных значений. Исключение SVG ровера, цвета внутри фигур, иначе он ломается при вставке в чужую карточку
- Onest (OFL) открытый гротеск с хорошей кириллицей.
- Весь UI свой, без UI-китов. Gravity UI (открытая дизайн-система Яндекса) заточена под рабочие инструменты - дашборды, консоли.

**Backend** (в работе):

- Kotlin + Ktor, kotlinx.serialization
- Exposed + Flyway, PostgreSQL в Docker
- Ядро - отдельный Gradle-модуль без зависимостей от Ktor и базы.
- Контракт между фронтом и бэком — `contracts/openapi.yaml`, из него генерируются TS-типы.

## Файловая структура

```
svoy-ritm/
    contracts/
        openapi.yaml       ← контракт API, из него генерятся типы для фронта
    design/
        svoy-ritm-ui-kit.svg       ← токены и компоненты, перетаскивается в Figma
        svoy-ritm-mvp-screens.svg  ← экраны 375×812, каждый отдельной группой
        rover.svg                  ← ровер отдельным файлом
    api/                   ← Kotlin + Ktor (Gradle, два модуля)
        engine/            ← чистое ядро, без Ktor и базы
        app/               ← роуты, сервис, Exposed, Flyway
    web/                   ← React + Vite + TypeScript
    docker-compose.yml     ← Postgres одной командой
```

Фронтенд и бэкенд независимые сервисы со своими конфигами, общаются по HTTP.

## Запуск

Нужен Node.js, для бэкенда дополнительно JDK и Docker.

**Фронтенд** (работает сам по себе, бэкенд не обязателен):

```bash
cd web
npm install
npm run dev
```

Откроется на `localhost:5173`. Данные живут в памяти браузера, F5 сбрасывает состояние — `localStorage` намеренно не подключён.

**Бэкенд:**

```bash
docker compose up -d        # Postgres
cd api
./gradlew :app:run
```

## Фронтенд

### Архитектура: четыре слоя

Собрано снизу вверх, каждый слой знает только о тех, что ниже.

| Слой | Что внутри | Знает про React | Знает про сеть |
| --- | --- | --- | --- |
| Движок | `applyEvent`, `format` | Нет | Нет |
| Стор | `StreakContext`, `useStreak` | Да | Нет |
| Компоненты | `Rover`, `Chip`, `DeadlineCard` | Да | Нет |
| Экраны | `Home`, `Cart`, `Rhythm` | Да | Нет |

Правило, по которому раскладывался код: компонент не считает, экран не рисует. Если в компоненте появляется «если остановок больше семи» — логика едет в движок. Если в экране появляется `<svg>` — он становится компонентом.

Практический смысл не в чистоте ради чистоты: когда появится бэкенд, поменяется ровно один файл `StreakContext`. Экраны и компоненты берут данные через `useStreak()` и не знают, откуда они приходят.

```
web/src/
    engine/            чистая логика, без React
        types.ts       ← StreakState, StreakPossibleEvent, вспомогательные типы
        applyEvent.ts  ← движок: правила ритма, окон, заморозок, наград
        format.ts      ← даты в родительном падеже и склонения
    store/
        StreakContext.tsx  ← useReducer поверх applyEvent + хук useStreak
    components/        кубики, которые только рисуют
        Rover.tsx          ← талисман серии, состояния через пропсы
        Chip.tsx           ← чип ритма в шапке главной
        DeadlineCard.tsx   ← карточка дедлайна, все пять состояний серии
        Route.tsx          ← маршрут-зигзаг снизу вверх к флажку цели
        Segments.tsx       ← сегментная полоска прогресса
        GoalCard.tsx       ← выбираемая карточка цели
        Button.tsx, Toggle.tsx, Coin.tsx, Battery.tsx
        ItemRow.tsx, ProductThumbs.tsx, Confetti.tsx
        DevPanel.tsx       ← панель демо
    screens/
        Home.tsx           ← главная Лавки: чип и плитка «Свой ритм»
        Cart.tsx           ← корзина, оформление отправляет PLACE_ORDER
        Delivered.tsx      ← подтверждение после доставки
        GoalChoice.tsx     ← выбор цели серии
        Rhythm.tsx         ← главный экран фичи
    styles/
        tokens.css     ← цвета, радиусы, шрифт
    app/
        App.tsx        ← провайдер стора, роутер, панель демо
```

### Движок

`applyEvent` - чистая функция, ничего не мутирует и не ходит в сеть. Возвращает новое состояние через spread.

Первое, что делает любое событие - `settle()`: проверяет, не истёк ли дедлайн, пока пользователя не было. Человек открыл приложение через неделю, и движок при первом же событии разберётся, потратить заморозку или прервать серию.

`settle` решает нужно ли действовать, `applyFreeze` и `breakStreak` - что именно сделать. Внутри этих двух нет ни одного `if`, так как вызываются только тогда, когда решение уже принято.

```ts
function settle(state: StreakState): StreakState {
  const { deadlineAt } = state;
  if (!deadlineAt || state.status !== "active") return state;
  if (Date.parse(state.now) <= Date.parse(deadlineAt)) return state;

  return state.freezesForStreak > 0
    ? applyFreeze(state, deadlineAt)
    : breakStreak(state);
}
```

События: `PLACE_ORDER`, `DELIVERY`, `CANCEL`, `ADVANCE_TIME`, `SET_GOAL`, `TOGGLE_FASTER`, `RESET`.

### Панель демо

Плавающая панель поверх приложения, шестерёнка справа внизу. Подменяет только то, что в жизни происходит без участия пользователя: доставку курьером и ход времени. Основной путь — главная → корзина → ритм → цель — живёт в самих экранах, панель не заменяет приложение.

Показывает текущее состояние движка (статус, уровень, остановки, ритм, заморозки, баланс) и журнал событий. Это же главный инструмент отладки: видно, что движок думает прямо сейчас.

Поле суммы заказа нужно, чтобы проверять порог второго уровня разными чеками.

### Симулированное время

Демо стартует с фиксированного момента — среда, 7 октября, — а не от системных часов. Сценарий получается воспроизводимым: даты на экране одинаковые при каждом запуске, скриншоты не расходятся с рассказом.

Кнопки "+12 часов" и "+1 день" двигают `state.now`, движок честно пересчитывает последствия. Так за минуту проверяется то, что в реальности заняло бы две недели: заморозка, обрыв серии, выход на второй уровень.

## Дизайн

Макеты в `design/`, оба SVG перетаскиваются в Figma как есть: каждый экран и каждый компонент отдельная группа с именем типа: `chip/at-risk` или `rover/charging`.

Цвета сняты пипеткой со скриншотов приложения Лавки. Ровер нарисован свой, по мотивам робота-доставщика: чёрный передний блок с фарой и лидаром, белый грузовой отсек, антенна с красным флажком.

Ровер работает талисманом серии, а не способом доставки: остановка засчитывается за любой доставленный заказ, кем бы он ни был привезён. В интерфейсе это проговаривается отдельной фразой для отсеивания вопросов, какой вариант доставки нужен для учёта прогресса.

| Состояние серии | Как выглядит ровер |
| --- | --- |
| Активна | едет по маршруту |
| Заказ в пути | едет с искрами движения |
| Заморожена | на зарядке, синяя панель |
| Оборвана | в гараже, выцветший |
| Второй уровень | с прицепом |
